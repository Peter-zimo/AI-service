# 企业级智能客服 Demo 加固设计

## 目标

在保留可选真实模型对话能力的前提下，使 Node.js 客服系统与 Python LangChain 服务能在无 API 凭据、断网环境中稳定启动、完成知识库检索，并收紧外部访问边界。

## 范围与约束

- 将当前未提交改动视为本次工作的基线，不回退或覆盖无关修改。
- 不读取、输出或修改现有 `.env` 中的真实凭据。
- 知识库索引、启动检查和测试默认不得访问外部模型或下载模型。
- 对话模型仍为可选能力：仅在用户消息未命中知识库且已显式配置有效供应商时调用。
- 保持 Node.js + SQLite 与 Python + FastAPI 的现有分层，不进行无关重构。

## 架构

### 离线优先知识库

Node 端知识库改为只使用 FTS/BM25 与现有本地 hash embedding。删除对 DeepSeek `/v1/embeddings` 的请求，以及对 Python `/api/embed` 的启动期依赖。新增或更新知识库时在本地重算向量，网络不可用不影响保存与检索。

Python 检索服务使用 `NODE_SQLITE_PATH` 指向 Node 的 SQLite 数据库；未配置时仅在已验证存在的当前项目相对路径中查找，找不到时清晰降级到内置知识库。BGE 只允许加载已存在的本地模型目录；缺失时直接使用本地 hash embedding，不尝试 Hugging Face 下载。

### 模型调用与失败降级

对话请求先做本地知识库匹配。只有未命中时，才创建并调用 DeepSeek/智谱 LLM。供应商缺失、连接失败或超时时，返回统一可理解的本地兜底答复与转人工提示，不再将网络问题写成知识库失败。

### 安全边界

客服 WebSocket 握手必须携带 JWT，并验证角色为 `admin` 或 `agent`，以及 token 中的主体与 `id` 一致。`ALLOWED_ORIGINS` 在生产环境必须配置；metrics 端点需要内部访问认证或显式开发开关。健康检查仅保留运行状态，避免暴露进程与内存细节。

### 测试策略

所有核心 RAG 回归测试应使用本地算法和临时数据库，不依赖端口 8000，也不得因 AI 服务未运行而跳过。为数据库路径解析、离线 embedding、WebSocket 鉴权、生产 CORS/metrics 添加回归测试。每项生产代码改动都遵循先失败、后最小实现、再全量验证。

## 数据流

1. 管理端新增或修改知识库条目。
2. Node 持久化条目，并在进程内生成本地 embedding。
3. 客户提问先经 Node FTS/BM25/本地向量检索；Python 服务也从同一 SQLite 路径读取并使用同样的离线降级策略。
4. 有高置信匹配时返回知识库答案；否则在已配置供应商时调用 LLM，失败时返回本地兜底。
5. 客服工作台连接 WebSocket 时先验证 JWT，失败则以 1008 关闭连接。

## 验收标准

- 无外部 API 凭据、网络不可用时，Node 与 Python 服务的健康检查和知识库检索可运行。
- 新增/更新知识库不再请求 DeepSeek embedding，也不触发模型下载。
- Python 默认不会读取旧 `workbuddy files` 数据库路径，并可通过 `NODE_SQLITE_PATH` 读取 Node 当前库。
- 无 JWT、无权限 JWT、token 主体不匹配的客服 WebSocket 均被拒绝；合法客服 token 可连接。
- 生产环境缺少 Origin 白名单时拒绝跨域访问，metrics 不再匿名暴露。
- RAG、离线降级和安全边界的新增测试无需外部服务且不会被 skip。
