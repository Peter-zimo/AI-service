# 知识库"答非所问"彻底修复方案

> 用户反馈：问"车坏了"却答"月卡/押金/忘拿东西"等无关内容。

## 一、根因（已通过运行诊断确认）

以 `车坏了` 为例（jieba 分词 `['车坏','了']`）：

| 检索 | 结果 | 原始分 |
|---|---|---|
| BM25 第一 | "车辆没电了怎么办" | 3.31（弱重合噪音） |
| 语义第一 | **"车上东西忘拿了怎么办"** | **0.592** ❌ |
| 语义第二 | "骑行中车辆出现故障怎么办"（真正的答案） | 0.582 ✅ |

**三层根因：**
1. **语义嵌入区分度不足**：BGE-small-zh 对该密集 FAQ 库，"车坏了"与"忘拿东西"(0.59) 相似度略高于真正故障条目(0.58)，仅差 0.01 → 语义检索选中错误条目。
2. **关键词覆盖不足**：故障类条目关键词是自动生成的 n-gram（"骑行中车辆出现"），**缺口语化同义词**（"车坏/坏了/单车坏/故障"），用户口语"车坏了"无法词面命中，只能靠不可靠的语义。
3. **BM25 噪音 + 阈值偏松**：单字/停用词（"了"）参与打分；`get_best_match` 语义阈值 0.45 放行了 0.55~0.60 误配区间，且采纳语义第一名即使与查询无词面支撑。

> 已排除"多套知识库不一致"：Node 与 Python 均从 `service_init.db`（54 条）加载，知识库唯一权威源，无测试垃圾条目。

## 二、修复方案

### A. 数据层（主修复，最有效）——扩充口语化关键词
在权威库 `service_init.db` 中为故障/损坏类条目补充口语同义词关键词，使口语查询能**词面强命中**：
- `骑行中车辆出现故障怎么办`：+ `车坏, 坏了, 单车坏, 车子坏, 车故障, 故障, 损坏, 报修, 骑不了, 走不了`
- `车辆没电了怎么办`：+ `没电, 没电了, 电量耗尽, 车没电`
- `如何上报车辆故障`：+ `报障, 故障上报, 上报故障, 坏车`
- `车辆质量问题怎么投诉`：+ `质量差, 坏车, 质量投诉`

同步更新镜像 `server/data/knowledge.json` 保持一致性。

### B. 算法层（辅修复，防再犯）——Python 检索加固 `knowledge/retriever.py`
1. `search_bm25`：过滤查询 token 中的**停用词与无意义单字**（白名单保留"车/锁/卡/点/账/金"等关键单字），减少弱重合噪音。
2. `search_legacy`：忽略 `<2` 字符的关键词，避免单字误命中。
3. `get_best_match`：改为**词面优先**——若 BM25 存在强命中（原始分 ≥ 3.5）直接返回该条目；仅当无强词面命中才用语义（阈值 0.45→0.5）。

### C. Node 端一致性（防御）`server/services/knowledge.js`
同步 `searchLegacy` 的短词过滤与 `getBestMatch` 逻辑，保持双端行为一致（Node 兜底路径）。

### D. 验证
1. 新增回归测试：`车坏了/单车坏了`→命中故障类条目；`月卡`→会员条目；`今天天气`→走 LLM。
2. 重启双服务，端到端复验批量查询。
