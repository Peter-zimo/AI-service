# AI 智能客服系统第二轮修复计划（安全 + 核心功能）

> **For agentic workers:** 使用 superpowers:test-driven-development 逐项修复，并用 superpowers:verification-before-completion 以真实运行验证。

**Goal:** 修复全面检查发现的高危问题（安全漏洞 + Python 核心功能 bug），使系统更安全、功能正常。

**Architecture:**
- Python LangChain 服务（`D:\AI应用\ai-service-langchain`）是 AI 对话核心；Node（`D:\AI应用\AI智能客服V3（node.js版）`）提供 Web/访客/管理端。

- 安全检查基于两轮 Explore 子代理深度审查 + 关键点人工核实。

**Tech Stack:** Python 3.13（workbuddy）、LangChain、FastAPI；Node.js（Express）+ better-sqlite3。

## 问题清单（来源：全面检查）

### Python 高危
- **H1** `ai/chat.py` _agent_chat：`tool_fn.invoke()` 同步调用异步工具（detect_user_emotion）→ 抛异常，情绪识别 100% 失效
- **M1** `ai/chat.py` `_direct_chat`/`chat_stream`：备用模型 `llm2.invoke`/`llm2.astream` 无异常保护
- **M2** `routers/api.py` chat_stream SSE：生成器无异常兜底，断流无 error 事件
- **H3** `ai/chat.py` _agent_chat：不注入对话历史，多轮无上下文
- **H5** `routers/api.py`：敏感/关键词批量端点无数量上限（成本/DoS）

### Node 安全高危
- **N1** `server/routes/chat.js`：visitorId 校验被 `if (visitorId)` 包裹 → 不带 visitorId 即绕过所有权校验（越权读写/操作任意会话）
- **N4** `public/admin.html:1328`：未答列表内联 `onclick` 存储型 XSS（`esc()` 在 onclick 里可被 HTML 实体解码逃逸）
- **N6** `server/routes/config.js` `/ai/detail`：返回完整 `apiKey` 到浏览器
- **N7** `server/middleware/auth.js` refreshToken：签发不含 role → 刷新后降级为 agent
- **N8** `server/middleware/auth.js` changePassword：未绑定当前登录用户，可改任意账号密码
